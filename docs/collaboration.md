# 팀원용 Codex 작업 방법

저장소 폴더에서 Codex를 열고 담당 GitHub Issue를 알려주세요. Issue, PR, 저장소 문서에 결정을 남기면 팀원이 각자의 Codex에서 같은 기준으로 작업할 수 있습니다.

| 순서 | 할 일 |
| --- | --- |
| 1. 범위 확인 | 담당 Issue와 앱별 AGENTS.md, 관련 API·디자인 문서만 확인합니다. 완료 기준이나 담당 범위가 모호하면 필요한 질문만 합니다. |
| 2. 계획 승인 | Codex가 목표, 수정 경로, 선행 조건, 검증 방법을 보고합니다. 개발자가 범위를 확인하고 승인합니다. |
| 3. 개발·검증 | 승인된 범위를 작업 브랜치에서 구현합니다. 계약이나 공통 파일을 바꿔야 하면 영향과 결정할 내용을 Issue에 남깁니다. |
| 4. 결과 보고 | 바뀐 내용, 실행한 검사와 결과, 남은 검증을 보고합니다. |
| 5. PR 게시 | 개발자가 결과와 PR 게시를 승인하면 브랜치를 푸시하고 Issue를 연결한 PR을 올립니다. |

## Codex에 붙여넣을 문장

> Issue #번호를 맡았어. 관련 지침과 문서를 읽고 필요한 질문만 해줘. 수정 경로와 검증 방법을 포함한 계획을 먼저 보여줘. 내가 승인하면 개발하고, 끝나면 결과를 보고해줘. 푸시와 PR 게시는 결과를 확인한 뒤 따로 승인할게.

## 짧은 보고 예시

- **계획** — 로그인 화면 구현. `apps/web` 로그인 화면 수정. 인증 API 경로 합의가 필요하며 성공·실패 화면을 Mock으로 검증.
- **결과** — 로그인 화면과 실패 안내 구현. 타입 검사와 Mock 검증 통과. 실제 API 연동 검증 대기.

Issue는 시작할 때 `In Progress`, PR을 올리면 `In Review`, 병합 후 완료 기준을 확인하면 `Done`으로 갱신합니다. 작업이 막히면 `Blocked`와 재개 조건을 기록합니다.
